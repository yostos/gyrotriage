# ADR-006: 解析区間の指定（--in / --out）

## ステータス

承認済み

## コンテキスト

gyrotriage はこれまでMP4内の全クォータニオン時系列を解析対象としてきた。しかしFPVドローンの飛行は局面によって運動特性が大きく異なる。

- **離陸直後** — 姿勢が不安定で大きな角速度変化
- **巡航** — 比較的安定
- **着陸前** — 減速・接地ショック

実際の編集ではDaVinci Resolve等のタイムラインに「採用する区間」だけを貼る。にもかかわらず全体をRMS/PSD平均すると、

- 巡航のきれいな区間でも離陸・着陸の暴れが混入してスコアが悪化する
- Smoothness / Zoom limit の推奨値が全区間をならした妥協値になり、実際に使う区間に対して過剰なクロップになりがち

つまり「実際に使う区間」に対しては、その区間だけで算出した方が正確なパラメータになる。

## 決定

**`--in` / `--out` オプションで解析区間（ソースタイムコード基準）を指定できるようにする。** 指定時はその区間のクォータニオンのみを解析対象とする。

- 既定（オプション無し）は従来どおり**ファイル全体**を解析する。これはトリアージ（ファイル選別）用途に適している
- `--in` / `--out` 指定時は、その区間だけで解析・スコアリング・推奨パラメータ算出を行う。これはタイムラインに採用した特定区間のチューニング用途に適している
- ADR-002（単一ファイル入力）と矛盾しない。入力は依然として単一ファイルであり、区間指定は抽出後のフィルタにすぎない

### 入力フォーマット

`--in` / `--out` は以下を受け付ける。

| 形式 | 例 | 解釈 |
|---|---|---|
| `HH:MM:SS:FF` | `00:00:18:07` | タイムコード（DaVinciのソースTC表示そのまま）。`:FF` はフレーム番号 |
| `HH:MM:SS` | `00:00:18` | 時:分:秒 |
| `MM:SS` | `00:18` | 分:秒 |
| 秒（小数可） | `18.5` | ファイル先頭からの経過秒 |

`HH:MM:SS:FF` はコロンが3つ。最後の `:FF` はフレーム番号であり、秒に換算するにはfpsが必要（→ fps取得）。

### fps取得

`:FF`（フレーム部）を秒に換算するためのfpsは、**`telemetry_parser::util::get_video_metadata()` でMP4コンテナから自動取得する**。ユーザーがfpsを意識する必要はない。

- `--fps <F>` で明示的に上書きできる（自動取得が0等を返す異常系のフォールバック）
- 自動取得に失敗し、かつ `:FF` が非ゼロのタイムコードが指定され、`--fps` も無い場合は**エラー**とする。誤差を黙って出すより、正確さを優先して明示を促す
- 秒指定（`18.5`）および `:FF` を含まない指定（`HH:MM:SS` 等）はfps不要

### 前提

ソースタイムコードはファイル先頭が `00:00:00:00` であること（録画開始時刻ベースのオフセットTCが埋め込まれていないこと）を前提とする。DJI Neo/Avata の通常素材はこの前提を満たす。クォータニオンの先頭サンプルをファイル先頭の基準とし、そこからの相対秒で区間を切り出す。

## 根拠

- 「採用区間だけ解析する」ことで推奨パラメータの精度が上がる、というのが本機能の主目的
- 入力フォーマットをDaVinciのソースTC表示（`HH:MM:SS:FF`）にそのまま合わせることで、ユーザーの転記コストを最小化する
- fpsをファイルから自動取得することで、`--fps` の手入力を不要にする

## 影響

- CLIに `--in` / `--out` / `--fps` を追加する
- `extract` はfpsを併せて取得して返す
- 区間指定時、出力に解析対象区間を明示する
- 区間が空または2サンプル未満になる指定はエラーとする
